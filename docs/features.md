## v1 のスコープ [確定]

**下の 13 機能すべてを v1 に含める。** 段階リリースをしない。

「2 つの提供形態で機能に差を設けない」（`overview.md`）を最初の版から実物で守るため。Web だけ先に出すと、差が無いことを確かめる手段（`adr/0010` のクライアント間整合テスト）が v1 の時点で成立しない。

**機能を落とす形での分割はしないが、実装の順序は持つ。** 順序は GitHub の Issue と Milestone で管理し、この文書には持たない。

## mmkn が持たないもの

**この一覧がこの事実の一次情報（正）。** 他の文書からは再掲せず、ここへリンクする。

以下はすべて [確定]。「今は作らない」ではなく「プロダクトの思想として持たない」と決めたもの。

| 持たないもの | 理由 |
|---|---|
| 収入 | 支払いと送金の 2 種類だけで、必要な金銭の動きを表現できる |
| 返金 | 専用の概念として管理しない。返金に伴って必要になった金銭の動きを、支払いか送金として記録すれば足りる |
| 借り | 送金に意味を持たせない。差額がその役割を果たす |
| 送金の目的 | 送金そのものだけを記録する。「なぜ送ったか」は結論に影響しない |
| 送金の充当先 | 特定の支払いとの対応関係を持たない |
| 精算済み | 清算案は導出値であり、確定させる対象ではない |
| 途中精算 | 特別な状態として扱わない。記録が増えれば結論が変わるだけ |
| 最終精算 | 同上 |
| 清算案の保存 | 常に現在の記録から導出する。保存すると記録との乖離が起きる |
| ペアごとの貸し借り | 差額から自動的に決まるため、別に持つ意味がない |
| 為替レート | 通貨間の計算をしない |
| 通貨間の合算 | 合算した金額に意味を持たせない |
| 送金手段 | 現金・銀行振込・送金サービスの違いを管理しない |
| メンバーの並び順 | 清算案のために順序を必要としない |
| オーナー・管理者 | 全メンバーを同等に扱う |
| メンバーの脱退・削除 | グループから抜けるという概念を持たない。抜けると過去の記録の意味が壊れる |
| グループの削除 | 作成されたグループは残る |
| 退会（アカウントの削除） | User を消すと Member が指す先が壊れ、過去の記録の意味が失われる。メンバーの脱退・グループの削除を持たないのと同じ理由。**ログアウトは持つ**（`domain/group.md`） |
| ユーザーを持たないメンバー（ゲスト） | メンバーは必ずユーザーに対応する |
| 操作者による権限の違い | 記録の登録者は保持するが、権限・計算・編集可否には使わない |
| 削除履歴 | 削除した記録は完全に消す。履歴を持つと「現在存在する記録」が曖昧になる |
| 外部サービスのアカウントだけでの利用 | mmkn のアカウントを主とし、外部アカウントはそこに紐づく連携として扱う。外部サービスのアカウントを失っても mmkn のアカウントに到達できる状態を保つ（`domain/group.md`） |
| 外部サービス側の集まりからのメンバーの取り込み | 外部サービス上の場にいることと mmkn の Member であることは無関係。参加は参加コードによる（`domain/group.md`） |
| 特定のクライアントにしかない機能 | Discord は数あるクライアントの 1 つとして扱う。どのクライアントも同じユースケースを呼ぶ（`adr/0004-layers-and-dependencies.md`） |
