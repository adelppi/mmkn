# Overview — mmkn

## 一行で

> グループ内で発生したお金の動きを記録し、その記録から「今、誰が誰にいくら送ればよいか」を導出するシステム。[確定]

## ビジョン [確定]

割り勘や立替が発生したとき、人は「誰がいくら払ったか」を覚えていられない。かといって、返金・キャンセル・現金で返した・アプリで送った……といった現実の出来事を一つひとつ管理し始めると、記録そのものが破綻する。

mmkn は、**現実の出来事を管理しない**。ユーザーが必要と思ったお金の動きだけを記録し、そこから機械的に結論を導く。

「精算が終わったかどうか」を管理するのではなく、**その時点で必要な送金を常に導出できる状態**をつくる。

## 提供価値 [提案]

- 記録するのは「支払い」と「送金」の 2 種類だけでよい。返金・立替・借りといった概念を覚える必要がない
- 「精算済み」を誰も管理しなくてよい。記録が正しければ、結論は常に自動的に正しくなる
- 通貨をまたぐ場面でも、通貨ごとに独立した結論が出る

## コアループ [確定]

お金の動きが発生したら、それを Payment（グループ外への支払いと負担者）または Transfer（メンバー間のお金の移動）として記録する。記録が変わるたび、通貨ごとのメンバーの差額と清算案が導出し直される。清算案に従って実際に送金したら、それをまた Transfer として記録する。すると次の清算案には、その送金が反映されている。

導出のルールは `domain/settlement.md` を正とする。

## やらないこと（プロダクトの考え方として持たないもの）[確定]

- **現実の出来事をモデル化しない。** ホテルのキャンセル、返金、立替の事情、送金手段などを専用の概念として持たない。ユーザーが必要と思った金銭の動きだけを記録する
- **「精算」を状態として持たない。** 精算済み・途中精算・最終精算といった状態を持たず、常に現在の記録から導出する

完全な一覧と理由は `features.md`「mmkn が持たないもの」を正とする。
