# ADR-0013: 通貨の一覧と最小単位を、自前の表としてドメイン層に持つ

- ステータス: 採用 [確定]
- 関連: `docs/domain/money.md`, `adr/0004-layers-and-dependencies.md`, `adr/0008-layer-internals.md`

## コンテキスト

`domain/money.md` は次を確定させている。

- 扱う通貨は **ISO 4217 の現行通貨**。通貨コードと最小単位の桁数は ISO 4217 に従う
- **最小単位の桁数を mmkn 側で独自に決めることはしない**
- 金額は「整数 + 通貨」で持ち、上限は最小単位で 1,000,000,000

つまり「どの通貨が存在するか」と「その通貨の最小単位が何桁か」を、実装が**どこかから得る必要がある**。ここが決まっていないと、金額の解釈そのものが実装ごとにぶれる。

制約は 2 つ。

- **この判定はドメイン層で要る。** 金額の妥当性（整数であること・上限）と負担額の配分（`domain/record.md`）が最小単位を前提にしている。`adr/0004` はドメイン層の依存先を「なし（言語標準のみ）」と定め、機械検査で外部パッケージと `node:*` を禁止している
- **同じ入力が常に同じ結果になる必要がある。** `adr/0010` はクライアント間で結果が一致することをテストで固定すると決めている

## 決定

**ISO 4217 の現行通貨のコードと最小単位の桁数を書き写した表を、ドメイン層に持つ。** 実行環境や外部パッケージから取得しない。

- 置き場は `src/domain/money/`（`adr/0008` のツリー）。値は `domain/money.md` が正とするものの**書き写し**であり、mmkn が独自に決めた値ではない
- 表に無い通貨コードは受け付けない。**「知らない通貨は最小単位 2 桁とみなす」といった既定値を置かない**
- ISO 4217 が改定されたときは、表を更新する。更新の手順は `docs/operations.md` を正とする

## 結果

- 良い点：
  - ドメイン層が依存をまったく持たないまま、金額の解釈を完結できる（`adr/0004` の機械検査にそのまま通る）
  - Web と Discord、手元と本番で結果が一致する。実行環境のバージョン差で通貨の一覧や桁数が変わる経路が存在しない
  - テストが決定的になる。「この環境ではこの通貨が無い」という形の失敗が起きない
- 留意点：
  - **ISO 4217 の改定に手で追随することになる。** 通貨の廃止・新設・桁数の変更は数年に一度の頻度だが、放置すると表と現実がずれる
  - **表そのものが 180 行ほどの静的データになる。** レビューでは中身より「どこから写したか」を見ることになるため、出典を表の先頭にコメントとして残す
  - 表に無い通貨を弾く以上、**新設された通貨は表を更新するまで使えない**。エラーとして出るため気づけるが、その場では回避できない

## 検討した代替案

- **言語標準の `Intl` から得る（`Intl.supportedValuesOf('currency')` と `Intl.NumberFormat`）**：依存が増えず、言語標準なのでドメイン層でも使え、改定への追随も実行環境の更新に乗る。ただし内実は CLDR であり **ISO 4217 と完全には一致しない**うえ、**実行環境のバージョンで一覧が変わり得る**。`domain/money.md` が「ISO 4217 に従う」と明記している以上、CLDR の内容がそのまま仕様になる状態は取れない。手元と本番でランタイムが違えば結果が変わる可能性も、`adr/0010` の「結果の一致で守る」方針と相性が悪い。
- **通貨データのライブラリを入れる**：一覧と桁数が固定され、改定への追随もライブラリの更新に乗る。ただし `adr/0004` がドメイン層の外部パッケージを機械検査で禁止しているため、インフラ層から値を渡す形になる。**金額の妥当性判定というドメインの中心的な処理が、外から注入された表に依存する**構造になり、ポートが 1 つ増える。得られるのは手作業の更新が消えることだけで、割に合わない。
- **DB のテーブルとして持つ**：管理画面から更新できる。ただし通貨の一覧は業務データではなく仕様であり、環境ごとに中身が違い得る状態を作る。ドメイン層が DB を知らない構造（`adr/0004`）とも衝突する。
- **使う通貨だけを列挙する（JPY・USD・EUR など数種類）**：表が小さく保守が軽い。ただし `domain/money.md` が「ISO 4217 の現行通貨」「特定の通貨を優遇しない」と確定させており、ドメインの決定を実装の都合で狭めることになる。海外旅行で使う通貨は事前に列挙できない。
