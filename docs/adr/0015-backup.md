# ADR-0015: バックアップはホスティング環境の標準機能に任せ、復旧できない範囲を明示する

- ステータス: 採用 [確定]
- 関連: `docs/overview.md`, `docs/features.md`, `docs/domain/record.md`, `adr/0005-data-access-and-authorization.md`, `adr/0011-ci-and-release.md`

## コンテキスト

mmkn が保存するのは金銭の記録であり、**失うと利用者が自力で復元できない**。加えて `features.md` は次を確定させている。

- **削除履歴を持たない。** 削除した記録は完全に消え、復元できない（`domain/record.md`）
- **グループの削除・メンバーの削除を持たない。** 消える経路をアプリ側に作らない

つまり mmkn 自身は「消えたものを取り戻す」手段を一切持たない設計であり、**データの保全はまるごと基盤側の責任になっている**。

`adr/0011` は「DB は 1 つしか持たない。無料の範囲で運用する」を制約として使っているが、その根拠が `overview.md` に明記されていなかった（`overview.md` が確定していたのは「ユーザーに課金しない」だけ）。この ADR で前提を確定させる。

## 決定

### 運用コストの前提

**mmkn は運用コストも無料枠に収める。** これを `overview.md`「前提」に確定した記述として置き、`adr/0011` と本 ADR の根拠にする。

個人が趣味で作るものであり、使い続けるかどうかが月々の支払いに左右される状態を作らないため。

### バックアップ

**ホスティング環境（Supabase）の標準機能に任せる。mmkn 側で定期ダンプの仕組みを持たない。**

- 独自のバックアップ処理・保管先・世代管理を実装しない
- **無料枠での保持期間と復旧の粒度を、着手時に実物で確認する**（手順は `docs/operations.md`）。「あると思っていたら無かった」が最も避けたい形であるため

### 復旧できない範囲を明示する

**次は復旧できない。** 個人開発で受け入れる範囲として、ここに明記しておく。

| 失われるもの | 理由 |
|---|---|
| 直近のバックアップ以降に登録された記録 | 保持の粒度が無料枠の機能に依存する |
| 利用者が自分で削除した記録 | 削除履歴を持たない（`features.md`）。バックアップの範囲外 |
| 誤って編集した記録の編集前の内容 | 編集前の内容を残さない（`domain/record.md`） |

**この範囲を狭めるための機能を、アプリ側に足さない。** 削除履歴を持たない・清算案を保存しないという決定は、いずれも「記録が唯一の正である」状態を保つためのものであり、復旧を目的に覆すと `features.md` の思想と衝突する。

## 結果

- 良い点：
  - 抱える仕組みが増えない。バックアップ処理の失敗を監視する対象も生まれない
  - 無料枠前提が文書として確定するため、`adr/0011`（DB を 1 つしか持たない、Preview を持たない）の根拠が埋まる
  - 復旧できない範囲を先に書いておくことで、「できると思っていた」という形の失望が起きない
- 留意点：
  - **無料枠のバックアップは保持期間が短く、粒度も粗い。** 何日前まで戻れるかは基盤側の都合で変わり得る
  - **利用者が増えて「失えないデータ」になった時点で、この決定は成立しなくなる。** そのときは無料枠前提の方を先に見直す
  - 着手時の確認（`docs/operations.md`）を飛ばすと、この ADR は「確認していない前提に乗った決定」になる

## 検討した代替案

- **定期ダンプを別の保管先に置く**：保持期間と粒度を自分で決められ、基盤側の都合に左右されない。ただし実行する場所（`adr/0003` はサーバーレスで常駐プロセスを持たない）、保管先、世代管理、そして**ダンプが失敗していることに気づく手段**まで必要になる。バックアップの失敗は静かに起き、必要になるまで分からない。個人開発で最も持ちたくない種類の仕組みである。
- **有料プランに上げて保持期間を延ばす**：最も確実で、実装は何も要らない。ただし「運用コストも無料枠に収める」前提と衝突する。**利用者が自分と周囲を超えた時点で、これが第一の選択肢になる**。
- **利用者が自分でデータを書き出せる機能を作る**：復旧を利用者の手に渡せる。ただし機能が 1 つ増え、`features.md` の一覧に入る話になる（現在は無い）。バックアップの代わりにはならず、書き出しを実行した人のデータしか残らない。
- **何も決めない**：着手は速い。ただし「バックアップがある」と暗黙に思ったまま進み、必要になった瞬間に無いことが分かる。この ADR の主目的は、その状態を避けることにある。
