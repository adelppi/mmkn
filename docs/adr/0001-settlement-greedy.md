# ADR-0001: 清算案の送金の組み合わせを貪欲法で求める

- ステータス: 採用 [確定]
- 関連: `docs/domain/settlement.md`

## コンテキスト

`domain/settlement.md` は、清算案について「差額を 0 にする」「送金件数はできるだけ少なくするが、常に最小であることは保証しない」までを定めており、**求め方そのものは規定していない**。その求め方をここで決める。

制約は次のとおり。

- ターゲットは旅行・パーティーなどのイベント（`overview.md`）であり、1 グループのメンバーは数人から十数人程度。数百人規模は想定しない
- 清算案は保存せず、表示のたびに導出し直す（`domain/settlement.md`）。したがって**導出は表示のたびに走る**
- 通貨ごとに独立して導出するため、扱う通貨が増えれば導出の回数もそのぶん増える
- 個人開発であり、保守できる複雑さに収める必要がある（`overview.md`）

## 決定

通貨ごとに、差額が 0 でない Member だけを対象として、次を繰り返す。

1. 差額が最も小さい（＝マイナス幅が最大の）Member を 1 人、差額が最も大きい（＝プラス幅が最大の）Member を 1 人選ぶ
2. 両者の差額の絶対値のうち**小さいほう**を送金額とし、「マイナス側 → プラス側」の送金を 1 件作る
3. 両者の差額からその額を差し引く。差額が 0 になった Member は対象から外す
4. 対象が空になるまで繰り返す

同じ差額の Member が複数いて選択が割れる場合は、`domain/record.md`「負担額の配分」で使うものと同じ **Member の変わらない同一性による順序**で先頭を選ぶ。これにより、同じ記録の集合からは常に同じ清算案が得られる。

## 結果

- 良い点：
  - 1 回の繰り返しで必ず 1 人以上が対象から外れるため、差額が 0 でない Member が n 人なら送金は **n-1 件以下**に収まる
  - 実装が短く、テストで全パターンを追いやすい。表示のたびに走らせても問題にならない計算量に収まる
  - 選び方が決定的なので、同じ記録からは何度導出しても同じ清算案になる。「見るたびに案が変わる」ことがない
- 留意点：
  - **件数が厳密な最小になるとは限らない。** 相殺し合う部分集合を見逃して、最小より 1〜2 件多い案を出す場合がある。これは `domain/settlement.md` が明示的に許容している範囲であり、欠陥ではない
  - 差額の絶対値の大きい者どうしを先に相殺するため、「大きい額を 1 回送る」案になりやすい。少額に分割したい利用者の意図は反映しない
  - 実装時は、繰り返しの中で差額が負にならないことをテストで担保する

## 検討した代替案

- **厳密に最小件数の解を求める**：相殺し合う部分集合をすべて探して分割する問題になり、計算量が人数に対して指数的に増える（部分集合和と同型で NP 困難）。イベント規模では実行できるとしても、表示のたびに走る導出でこの複雑さを抱える理由がない。そもそも `domain/settlement.md` が最小を保証しないと決めているため、要件を満たすために必要ですらない。
- **差額が完全に相殺し合う部分集合を先に分離してから、残りを貪欲法で処理する**：件数が減る場合はある。ただし部分集合の探索が加わって実装量と計算量の両方が増え、その割に減るのは数人規模では多くて 1〜2 件。最初の版では釣り合わない。件数の多さが実際に不満として出てきたら、この ADR を覆して再検討する。
- **ペア単位の貸し借りをそのまま送金にする**：誰が誰に払ったかの対応関係を保持することになり、`features.md`「持たないもの」の「ペアごとの貸し借り」「送金の充当先」と正面から衝突する。送金件数も大きく増える。
