# ADR-0002: 参加コードを cuid2 で生成する

- ステータス: 採用 [提案→要承認]
- 関連: `docs/domain/group.md`, `adr/0003-tech-stack.md`

## コンテキスト

`domain/group.md` は参加コードについて「グループ作成時に生成し、変更・再生成しない」「共有リンクに埋め込んで渡し、ユーザーが手で入力する経路は持たない」までを定めている。その形式と生成方法をここで決める。

手入力しないと決めたことで、次の制約が外れる／加わる。

- **外れた制約**：人が読み上げられること、覚えられること、短いこと。紛らわしい文字を除外する必要もない
- **加わった制約**：リンクをそのまま貼れること。URL に含めても壊れず、エスケープが要らない文字だけで構成される必要がある
- **残る制約**：グループ間で衝突しないこと。**発行済みのコードから、他のグループのコードを推測できないこと**。参加コードを知っていれば誰でも参加できる（`domain/group.md`）ため、推測できてしまうとそのまま他人のグループに入れてしまう

提供形態は Web アプリと Discord アプリの 2 つ（`overview.md`）。この 2 つを同じ実装で賄うため、実行環境は TypeScript になる（`adr/0003-tech-stack.md`）。

## 決定

参加コードは **cuid2（`@paralleldrive/cuid2`）の既定設定で生成した文字列**とする。

- 文字種は英小文字と数字のみ、先頭は必ず英字。URL エスケープが不要で、リンクにそのまま埋め込める
- 長さは既定の 24 文字を使う。短縮設定は使わない
- 生成はグループ作成時の 1 回だけ。以後、変更も再生成もしない（`domain/group.md`）
- 衝突は起きない前提に**しない**。生成した値が既存のグループと重なっていた場合は、生成し直してから作成を完了する

将来 JavaScript / TypeScript 以外の実行環境が加わった場合は、この ADR を覆すのではなく、同等の性質（URL セーフ・乱数由来・24 文字相当の長さ）を持つ生成方法に読み替える。

## 結果

- 良い点：
  - 乱数由来で並びに規則性がないため、発行済みのコードから他のコードを推測できない
  - 24 文字の英数字は十分な組み合わせ数があり、衝突をアプリ側で頻繁に処理する事態にならない
  - ライブラリが 1 つ増えるだけで、自前の生成ロジック・文字種の選定・偏りの検証を持たなくてよい
- 留意点：
  - **cuid2 を使う。無印の `cuid`（v1）は使わない**（理由は代替案の項）
  - 共有リンクを知っている人は誰でも参加できる。リンクの流出はそのままグループへの参加を許すことになるが、これは「参加コードで参加する」というドメインの決定（`domain/group.md`）の帰結であり、生成方法で解決する問題ではない
  - 手入力の経路を持たない前提に依存している。将来コードの手入力を認めるなら、24 文字は現実的でないためこの ADR を見直す

## 検討した代替案

- **無印の `cuid`（v1）**：作者自身が非推奨としており、更新が止まっている。加えて v1 の値はタイムスタンプと連番のカウンタを含むため、**発行済みのコードから前後に発行されたコードを推測できてしまう**。参加コードは知っていれば参加できる鍵そのものなので、この性質は許容できない。
- **UUID v4**：推測できない点は満たす。ただしハイフンを含む 36 文字で、cuid2 より長いのにリンクとしての扱いやすさは劣る。導入するライブラリの数は変わらないため、選ぶ利点がない。
- **標準の乱数生成器から URL セーフな文字列を自前で作る**：依存が増えないのが利点で、技術スタックが変わっても持ち運べる。ただし文字種の選定・長さの決定・偏りの検証を自分で抱えることになり、個人開発で持つ責務としては割に合わない。スタック確定後に依存を減らしたくなったら、この案に戻す余地は残しておく。
- **連番や、グループ名から作った短いコード**：短くて扱いやすいが、次のコードが自明に推測できる。手入力しないと決めた以上、短さに価値がない。
