# ADR-0017: クライアントを Web だけにし、Discord クライアントを廃止する

- ステータス: 採用 [確定] — 2026-11-24
- 関連: `docs/overview.md`, `docs/features.md`, `docs/domain/group.md`, `adr/0003-tech-stack.md`, `adr/0004-layers-and-dependencies.md`, `adr/0006-discord-http-interactions.md`（廃止）, `adr/0010-testing.md`, `adr/0011-ci-and-release.md`, `adr/0012-login.md`

## コンテキスト

mmkn は Web と Discord の 2 つのクライアントを持ち、差を設けないことを前提にしていた（`adr/0003`・`adr/0004`・`adr/0006`）。実装を終えて見直すと、次の状態だった。

- **差は既にあった。** 記録の編集・削除・一覧、表示名とグループ設定の変更、参加は Web にしか無く、場の対応づけは Discord にしか無かった。整合テスト（`adr/0010`）は両方に入口がある操作だけを比べるため、この差を検出できなかった
- **コストはクライアント 1 つ分に見合わなかった。** Discord のアダプタが層の中で最も大きく、3 秒制限・モーダル・可視性・コマンド登録という、mmkn の中心（収支と清算案）に関わらない制約を抱え続けていた
- **認証の複雑さの多くも、ここから来ていた。** 届いた操作の主を解決するためだけに、認証基盤の内部テーブルを直接読んでいた
- **個人開発であり、使われ方に対して保守する対象が多すぎた**（`overview.md`「前提」）

## 決定

**クライアントを Web だけにする。**

- Discord のアダプタ・署名検証・エンドポイント・コマンドの登録と診断・クライアント間整合のテストを持たない
- 場と Group の対応、外部サービスから届いた操作の主の解決を持たない
- **Discord でのログインは残す。** それは OAuth の提供元としての利用であり、クライアントではない（`adr/0012`）
- **層の分け方と依存の向きは変えない**（`adr/0004`）。クライアントが 1 つでも、導出をフレームワークと DB から切り離す理由は残る
- 廃止する直前の状態は、タグ `discord-client-final` から参照できる

## 結果

- 良い点：
  - 保守するコードと docs が減り、リリースが 1 段短くなる
  - 実行時に要る秘密情報・外部サービスの設定が減る（署名検証の公開鍵・Bot Token・Application ID）
  - `docs/` の「差が無い」と実装の間にあった食い違いが解消する
- 留意点：
  - **チャットの中から記録できなくなる。** 清算案を会話に公開する手段も無くなる
  - **登録済みのコマンドは、Discord 側から別に解除する。** コードを消しても残り、押すと応答が無い状態になる（手順は `docs/operations.md`「リリース」）
  - 場と Group の対応のデータは、テーブルを落とした時点で戻せない（`adr/0015`）

## 検討した代替案

- **Discord にも足りない操作を実装し、差を無くす**：元の前提を守れる。ただし抱えている制約がさらに増え、得られるのは Web で済んでいることの重複になる。
- **Discord を「記録と確認だけ」のクライアントとして残す**：実装を減らさずに docs だけを実態に合わせられる。ただしコストの大半はアダプタを持つこと自体にあり、ほとんど減らない。
- **通知だけを Discord に送る**：会話に清算案を出せる。ただし外部への送信と、その失敗の扱いを抱えることになる（`adr/0014` は通知を持たないと決めている）。必要になった時点で、この ADR を覆さずに足せる。
- **Discord でのログインも廃止する**：外部サービスとしての Discord が完全に消える。ただし既存の利用者は全員 Discord でログインしており、自分の User に到達できなくなる。
